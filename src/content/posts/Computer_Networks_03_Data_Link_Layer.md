# 使用点对点信道的数据链路层

## 数据链路和帧

链路（Link）：链路是一条无源的、点到点的物理线路段，中间没有其他交换结点

数据链路：只有物理链路还不够，我们还需要解决其他问题如数据从哪开始、出错了怎么办，所以需要协议，那么数据链路就是链路加上实现数据传输控制**协议**的硬件和软件，典型实现就是网络适配器，或者说网卡

帧（Frame）：帧是数据链路层的协议数据单元 PDU ，在这里就是把网络层的 IP 数据报装入数据链路层的帧中发送

## 三个基本问题

### 封装成帧

当网络层给下来一个 IP 数据报，对于接收方来说，它需要知道从哪里开始、在哪里结束，所以需要在这个报文两边加上帧首部和帧尾部，首部和尾部还携带控制信息。接收方依据具体协议规定的定界方式识别帧边界，这就是**帧定界**；并非所有协议都用专门的开始、结束字符

```text
帧首部           帧尾部
 ↓                 ↓
[ Header | 数据 | Trailer ]
```

MTU（Maximum Transfer Unit）：最大传送单元，这里指链路能够承载的最大网络层分组长度，通常对应帧的有效负载上限，不包括链路层首尾部；普通以太网的 IP MTU 常为 1500 B，不等于 1518 B 的最大 MAC 帧长

### 透明传输

用字符定界协议举例，约定 SOH = 帧开始、EOT = 帧结束，一个帧如下（这不是所有链路层协议的统一格式）

```text
SOH | hello world | EOT
```

但如果我们要传输的数据为

```text
hello EOT world
```

那么实际会发送

```text
SOH | hello EOT world | EOT
```

此时接收方会误认为帧直接结束，从而导致数据损坏

这里的**透明**，指的是数据内容不能干扰协议对控制信息的识别。即使数据中出现 SOH、EOT，也应能正确传送并还原，所以透明传输 = 任意比特组合都能作为数据传输

解决方法：字节填充 / 字符填充

引入特殊字符 ESC ，当数据中出现 SOH、EOT 之类的控制字符，或 ESC 本身，我们在前边填充 ESC ，告诉接收方后面的 EOT 是普通数据，不是真正的帧结束标志，那么实际发送时如下

```text
SOH | hello ESC EOT world | EOT
```

### 差错检测（CRC 循环冗余检验）

在传输过程中会出现某位比特反转导致错误传输，叫做**比特差错**

误码率（BER）：在一段时间内，传输错误的比特占所传输比特总数的比率

为了检验是否出现错误，引入方法 CRC ，核心思想就是发送方给原始数据算出一个“校验尾巴”，接收方重新检查这个尾巴是否匹配

接下来看 CRC 如何工作。假设原始数据 $M=101001$，生成多项式对应的除数 $P=1101$，其最高次数为 $r=3$。

1. 先在原始数据后补 $r$ 个 0，得到 $101001000$。
2. 用 $P$ 对补零后的数据做**模 2 除法**（减法用异或，不借位），得到余数 $R=001$。
3. 把余数补足 $r$ 位并替换末尾的 0，发送 $M|R=101001001$。

$$
R=(M\cdot 2^r)\bmod P
$$

这里的乘法表示比特串左移，取余是多项式的模 2 运算，不是普通整数取余。接收方用同一个 $P$ 除收到的整个码字；余数非零，说明检测到了差错；余数为零，只能说明**未检测到差错，不保证绝对无错**。详情可见信息论纠错编码部分

帧检验序列（FCS）：为了进行检错而添加的冗余码，在这个简化 CRC 例子里就是上边计算出的 $R$。实际协议还会规定初始值、比特顺序、最终异或等，不能直接用此玩具例子的全部步骤代替协议实现

# 点对点协议 PPP

PPP：用于**点对点链路**的数据传输协议

PPP 的三个组成部分：

1. 将网络层数据报（如 IP 数据报）封装到串行链路上的方法
2. LCP（Link Control Protocol）链路控制协议
3. NCP（Network Control Protocol）一组网络控制协议，用于配置不同的网络层协议

## PPP 帧格式

以下是未启用字段压缩时的常见 PPP 帧格式；信息字段的默认最大接收单元为 1500 B，可通过 LCP 协商。

| 字段 | 长度 | 含义 |
| --- | --- | --- |
| F | 1 B | Flag，固定为 0x7E，用于帧定界 |
| A | 1 B | Address，固定为 0xFF；点对点链路无需区分多个目的站 |
| C | 1 B | Control，固定为 0x03，表示无编号信息帧 |
| Protocol | 2 B | 说明信息字段所承载的协议 |
| Information | 默认最大 1500 B | 真正要传输的数据 |
| FCS | 通常 2 B | 帧检验序列，也可协商使用 4 B |
| F | 1 B | 结束标志，同样为 0x7E |

## PPP 中的透明传输

按定界方式区分，课内常见的两种情况是：

- **异步传输使用字节填充**：以 0x7D 为转义字节，后面的原字节与 0x20 异或。例如，0x7E → 0x7D 0x5E，0x7D → 0x7D 0x5D；按控制字符映射要求，还可能转义其他控制字节。接收方执行逆变换。
- **面向比特的同步传输使用零比特填充**：标志 0x7E 写成二进制为 01111110。发送方在两个标志之间的内容中，每遇到连续 5 个 1，就插入一个 0；接收方按规则删除这个 0。标志本身不做填充。

注意：同步传输也存在面向字节的形式，所以不能一概认为“所有同步传输都用零比特填充”。

## PPP 工作状态

先建立物理连接，再用 LCP 建立并配置链路；如果协商了身份鉴别，就进行鉴别；随后由 NCP 配置网络层协议，进入可传输数据的状态。结束时关闭网络层协议、终止链路并释放物理连接。PPP 提供差错检测，但本身不靠确认和重传保证可靠交付

# 使用广播信道的数据链路层

与前边的 PPP 不同，这里是多个主机共享同一条信道，那么问题随之而来，若两台机器同时发送该怎么办，这就是这一部分的主线

## 局域网的数据链路层

局域网 LAN：覆盖范围较小，通常由一个单位拥有和管理；设备数量受具体组网条件限制。

局域网的拓扑结构：总线型、环形、星型

![局域网常见拓扑结构](/images/computer-networks/03-02.png)

媒体接入控制（MAC）：多个设备共享一条广播信道，如果同时发送数据，就可能互相干扰，导致发送失败，这时候就需要 MAC 控制多个设备如何共享通信介质

解决方案：
- 静态划分信道：物理层学的各种复用
- 动态媒体接入控制：随机接入（CSMA/CD）、受控接入

以太网两个标准：
- DIX Ethernet V2
- IEEE 802.3

IEEE 802 局域网体系将数据链路层分为两个子层（不是所有链路层协议都这样划分）

```text
数据链路层
│
├─ LLC
│  Logical Link Control
│  逻辑链路控制
│
└─ MAC
   Medium Access Control
   媒体接入控制
```

网卡：计算机一般是将数据经过网卡处理后再发送到网络上，网卡主要负责串并转换、缓存、收发帧、实现以太网协议

## CSMA/CD ★

以下讨论共享介质、半双工以太网。现代交换式全双工以太网不使用 CSMA/CD

| 缩写 | 全称 | 含义 |
| --- | --- | --- |
| MA | Multiple Access | 多点接入，多台主机共享同一条信道 |
| CS | Carrier Sense | 载波监听，发送前判断信道是否空闲 |
| CD | Collision Detection | 碰撞检测，发送过程中检查是否发生碰撞 |

简记为：先听后发，边发边听，冲突停止，随机重发

**发送流程**：监听信道 → 忙则继续监听 → 空闲并满足帧间间隔要求后发送 → 边发边检测；若碰撞，发送强化碰撞信号后停止本次发送，执行随机退避，再重新监听。正常发送完毕则结束

有一个关键问题，为什么都先听后发了，还是会出现碰撞？

假如 A 和 B 相距很远，A 在 t=0 时刻发送信号，设 A 到 B 的传播时间为 $\tau$ ，那么当信号还在路上时，B 监听到的仍是信道空闲，所以它也尝试发送信号，从而导致碰撞

所以本质原因是存在**传播时延**

**争用期/碰撞窗口** = $2\tau$

这里的 $\tau$ 是网络最远两站之间的单程传播时延。最坏情况下，B 在 A 的信号到达前一瞬间开始发送，B 的信号再传播回 A，A 检测到碰撞时已接近 $2\tau$。这不是 B 收到数据后专门回复一条“冲突通知”

那么如果一台机器发送数据后，经过整个争用期 $2\tau$ 都没有检测到冲突，那么就可以认为本次发送之后不会再发生冲突

争用期的物理依据是最大往返传播时延，与网络跨度、信号传播速度及中继设备时延有关；标准据此规定时隙并限制网络规模。10 Mbit/s 半双工以太网的标准时隙为 512 比特时间，即 **51.2 μs**；100 Mbit/s 时为 **5.12 μs**。不能把 51.2 μs 套用于所有以太网

对于 `10 Mbit/s` 以太网，在一个争用期内可以传输 512 bit ，也就是 64 字节，因此得出**最短帧长**为 64 字节

如果一个帧过于短，那么可能出现 A 已经发完了整个帧才收到碰撞信号，就无法做到边发送边检测，所以要保证帧发送时间大于等于最大往返传播时延。64 B 从目的 MAC 地址算到 FCS，不包括前同步码和帧开始定界符。一般计算题可先用 $L_{\min}\geq 2\tau C$ 判断最短帧长，其中 $L$ 用 bit、$C$ 用 bit/s、$\tau$ 用 s；以太网标准时隙还包含相应物理层时延预算

发送方发现数据太短，应先填充以满足最短帧长；接收方收到不足 64 B 的短帧，则将其视为无效帧丢弃

如果发生了碰撞，就需要等待一段时间再发，这里使用的方法是**二进制指数退避**

规则如下：

1. 基本退避单位为一个时隙，课内记为 $2\tau$。
2. 设同一帧已发生 $n$ 次碰撞，令 $k=\min(n,10)$。
3. 从 $\{0,1,2,\ldots,2^k-1\}$ 中随机选一个整数 $r$。
4. 本次退避时间为 $r\times 2\tau$；等待后重新监听信道，再按规则发送。
5. 同一帧连续 16 次发送尝试都因碰撞失败时，放弃该帧并报告错误；不要理解成首次发送失败后还能额外重传 16 次。

碰撞次数增加时，可选的随机等待范围扩大，降低再次“撞在一起”的概率；$k$ 最大取 10，所以等待范围不会无限增大。

## 使用集线器的星形拓扑

传统以太网：
- 粗同轴 → 细同轴 → 双绞线

双绞线以太网采用星形拓扑，中心设备为集线器（Hub）

10BASE-T：
- 10     → 10 Mbit/s
- BASE   → 基带传输
- T      → 双绞线

集线器：
- 集线器工作在物理层
- 本质上类似一个多接口转发器
- 虽然物理拓扑是星形，但逻辑上仍然是总线网
- 各站仍然共享信道，仍然使用 CSMA/CD

## 以太网的信道利用率

我们已经有了单程传播时延 $\tau$ 和争用期 $2\tau$ ，再设帧长 $L$ 和发送速率 $C$ ，那么发送一个帧需要 $T_{0}=L/C$

在忽略碰撞、退避、帧间间隔等开销的简化模型中，从开始发送到最远端收完最后一比特，需要 $T_{0}+\tau$

$$
a=\frac{\tau}{T_{0}}
$$

这个参数反映传播时延相对于帧发送时间的大小。在上述理想化模型中，极限信道利用率为 $S_{\max}=1/(1+a)$；$a$ 越小，理想利用率越高。实际利用率还受碰撞、退避和负载影响，不能直接等同于这个上限

## 以太网的 MAC 层

MAC 地址也叫做硬件地址、物理地址，使用的是 48 位地址，MAC 地址标识的是**网络接口**，不是整台计算机。比如一台电脑同时有有线网卡和无线网卡，就可以有两个 MAC 地址

对于常见的、基于 24 位 OUI 分配的全球管理地址，前 24 位为 IEEE 分配的*组织唯一标识符*，后 24 位由组织自行分配。下图表示这种分配方式；本地管理地址（如随机化 MAC 地址）不能直接按厂商 OUI 解读

```text
┌───────────────┬───────────────┐
│ 前 24 bit     │ 后 24 bit     │
├───────────────┼───────────────┤
│ OUI           │ 扩展标识符     │
│ IEEE 分配     │ 厂商自行分配    │
└───────────────┴───────────────┘
```

- 单播：一对一
- 多播：一对多
- 广播：对同一广播域内的所有设备，此时广播的地址为 FF:FF:FF:FF:FF:FF

正常接收模式下，网卡会检查目的地址，接收发给本接口的单播、广播以及已配置接收的多播帧，并检查帧是否有效；不是只接收“目的地址等于自己”的帧。混杂模式下的过滤规则另当别论

### 以太网的 MAC 帧格式 ★

这部分主要讲不带 VLAN 标签的 Ethernet V2 帧，字段顺序如下：

| 字段 | 长度 | 作用 |
| --- | --- | --- |
| 目的地址 | 6 B | 告诉网络这个帧要发给谁 |
| 源地址 | 6 B | 说明谁发的 |
| 类型 | 2 B | 指明数据应交给哪个上层协议 |
| 数据及填充 | 46～1500 B | 承载上层数据，不足最小长度时填充 |
| FCS | 4 B | 检测差错，发现错误则丢弃 |

首部共 14 B，尾部为 4 B。因此最小数据及填充长度为 64 − 18 = 46 B，最大帧长为 1500 + 18 = 1518 B。填充内容不属于上层原始数据，不应把“必须全部填 0”当成帧格式要求。

发送时，在 MAC 帧之前还有 8 B 用于同步和定界：

| 前同步码 | 帧开始定界符 | MAC 帧 |
| --- | --- | --- |
| 7 B | 1 B | 目的地址 → 源地址 → 类型 → 数据及填充 → FCS |

前同步码让接收方实现比特同步；帧开始定界符表示 MAC 帧马上开始。这 8 B 不计入 64～1518 B 的 MAC 帧长度。帧间间隔也不属于 MAC 帧。

# 扩展的以太网

## 物理层扩展以太网

最典型的方法是使用集线器（Hub）来把多个以太网连接在一起，从而扩大网络覆盖范围，但是缺点是不会隔离碰撞域，且总吞吐量也没有提高

## 数据链路层扩展以太网 ★

这里利用的是**交换机**（Switch）

交换机利用目的 MAC 地址决定帧从哪个接口出去，本质上可以理解成多端口网桥。它隔离各端口所连接网段的碰撞域；端口采用点对点全双工连接时，不会发生碰撞，各链路独享带宽，但总吞吐量仍受交换机能力等因素限制

### 自学习

这是交换机最重要的工作机制之一，交换机根据 MAC 地址表来查询地址，这个表在最开始是空的

假设

```text
   Switch
1   2   3   4
|   |   |   |
A   C   B   D
```

那么当 A -> B 时，帧从接口 1 进入交换机，那么在此帧中包含源地址 A 和目的地址 B，交换机会先学到 A -> 端口 1 ，这就是交换机通过帧的“源 MAC 地址”学习；然后查询目的地的地址，但此时不知道 B 的端口，于是选择*泛洪*，即向同一 VLAN 内除入端口外、处于转发状态的其他端口转发，当 B 回信之后，交换机又学到 B -> 端口 3，于是 MAC 地址表变成

```text
MAC    端口
A      1
B      3
```

可以总结为：**学源地址，查目的地址**。如果查出的出端口就是入端口，则过滤该帧，不再转发回去

最后还有*有效时间*，因为动态 MAC 表项需要适应设备移动，一段时间未刷新后会老化删除，再自动学习；静态配置的表项不按此规则老化，所以交换机可以做到即插即用

### 环路问题

在实际使用过程中，我们可能会把交换机连成一个环路，若此时有未知单播帧或广播帧进入，就可能在环路中不断绕圈子

因此引入 **STP 生成树协议**

核心思想：物理线路可以保留，但逻辑上阻塞一部分链路，让整个网络形成无环的树结构

## VLAN 虚拟局域网 ★

尽管交换机可以隔离碰撞域，但是广播依旧会传播给很多主机，所以我们需要 VLAN

VLAN 是对局域网进行的逻辑划分，一个 VLAN 对应一个广播域。常见做法是把交换机端口划入某个 VLAN；不同交换机上的端口也可属于同一 VLAN，因此不必按物理位置划分。交换机依据端口配置或帧中的 VLAN 标签确定归属，并不是每个线上传输的帧都显式带标签

比如构建成：

```text
Switch
│
├─ A ─ VLAN 10
├─ B ─ VLAN 20
├─ C ─ VLAN 10
└─ D ─ VLAN 20
```

虽然四个主机都在同一个交换机下，但是逻辑上可以变成

```text
VLAN 10：A、C

VLAN 20：B、D
```

同时一个 VLAN 就是一个广播域，那么 A 发广播时只有 C 可以接收到，但是 B、D 接收不到。不同 VLAN 之间通信通常需要路由器或三层交换机进行三层转发

### 802.1Q VLAN 帧

在需要通过同一链路区分多个 VLAN 时，常使用 802.1Q 标签：在源 MAC 地址之后插入 4 B 的 VLAN Tag。终端接入端口通常收发无标签帧，由交换机根据端口配置判断 VLAN 归属

```text
目的MAC | 源MAC | VLAN Tag | Type | Data | FCS
```

VLAN ID 占 12 bit，有 4096 种编码，但 0 用于优先级标记、4095 为保留值，通常可用于标识 VLAN 的编号是 **1～4094，共 4094 个**。设备实际支持的数量可能更少。增加标签后，普通带标签以太网帧的最大长度为 1522 B（不计前同步码和帧开始定界符）

# 高速以太网

## 100BASE-T

快速以太网 Fast Ethernet

- 速率：100 Mbit/s
- 标准：IEEE 802.3u
- 拓扑：星形拓扑

特点：
- 保持 IEEE 802.3 MAC 帧格式
- 可采用半双工或全双工，具体取决于物理层类型和设备
- 半双工使用 CSMA/CD；全双工无碰撞，不使用 CSMA/CD
- 最短 MAC 帧长仍为 64 B；100 Mbit/s 半双工的时隙仍为 512 比特时间，即 5.12 μs，允许的网络跨度也受到限制

## 吉比特以太网

速率：1 Gbit/s

特点：
- 支持半双工 / 全双工
- 保持 IEEE 802.3 MAC 帧格式
- 半双工 → CSMA/CD
- 全双工 → 不使用 CSMA/CD
- MAC 帧格式保持兼容；能否以 10/100 Mbit/s 工作取决于端口是否支持相应速率，不能认为所有吉比特接口都自动支持

半双工特殊机制：
- 载波延伸：对短帧补充非数据的延伸符号，使载波持续时间满足 4096 比特时间的时隙要求，MAC 帧本身的最短长度仍为 64 B
- 分组突发：一次获得信道后连续发送多个帧，提高短帧传输效率

## 10GE

速率：10 Gbit/s

特点：
- 保持原来的 Ethernet MAC 帧格式
- 保持最小、最大帧长
- 只工作在全双工方式
- 无碰撞
- 不使用 CSMA/CD

更高速：40GE、100GE

## 以太网宽带接入

PPPoE：PPP over Ethernet

即：在以太网中承载 PPP。会话阶段的封装关系是“以太网首部 → PPPoE 首部 → PPP 协议字段及数据 → 以太网 FCS”，不是原封不动地嵌入串行链路上的整套 PPP 定界与 FCS 字段。普通 1500 B 以太网负载扣除 6 B PPPoE 首部和 2 B PPP 协议字段后，常见 IP MTU 为 1492 B

# 用生活中的例子理解链路层

## 1. 封装成帧：给快递装箱

寄快递时，不能把所有人的东西混在一起直接交给快递员，而是要分别装箱，让人知道哪些东西属于同一个包裹。

封装成帧也是类似的过程：网络层交下来的 IP 数据报相当于要寄的物品，链路层给它加上首部和尾部，组成一个帧。接收方按照协议规定的定界方式，识别一帧从哪里开始、在哪里结束，才能把里面的数据取出来。

所以我理解，**封装成帧就是给连续传输的数据划清边界，让接收方能够一帧一帧地处理**。首部、尾部还可以携带地址、校验等控制信息，具体取决于使用的协议。

## 2. 透明传输：口述内容里也有“结束”两个字

假设我请同学记录一段话，事先约定听到“结束”就停止记录。但如果我要说的内容本身就是“这场比赛结束了”，同学可能听到中间的“结束”就提前停下。

解决办法是再约定一个“转义”口令：听到“转义、结束”时，就把“结束”当作正文记下来，而不是停止记录。如果正文里本身出现“转义”，也要用同样的规则说明它是正文。

这对应链路层的字节填充：数据里出现定界符时，在前面加转义字符；数据里出现转义字符本身时，也需要转义。接收方按规则去掉额外添加的字符，就能恢复原始数据。

所以**透明传输不是传输过程中完全不改动数据，而是无论原始数据是什么，都能被正确传送并还原，不会被误当作控制信息**。

## 3. 为什么先监听再发送，还是会碰撞：操场两端同时喊话

假设两个人站在操场两端，约定先听有没有人说话，安静时才开口。A 先喊了一声，但声音传到 B 那里需要时间。如果 B 在声音到达前也准备说话，就会觉得现在没人说话，于是也开口，最后两人的声音混在一起。

共享信道也是这样：A 已经开始发送，不代表 B 立刻就能监听到。只要 A 的信号还没有传播到 B，B 就可能判断信道空闲并开始发送，从而发生碰撞，哪怕两者并不是严格同时开始发送。

所以根本原因是**信号传播需要时间，监听到的只是本地此刻的状态，不能立即知道远处是否已经开始发送**。载波监听可以减少碰撞，但不能完全避免碰撞；CSMA/CD 还需要边发送边检测碰撞。

## 4. MAC 帧首部为什么需要这些字段：快递面单和物品类别

以 Ethernet V2 帧为例，可以把它的首部理解成快递包裹上的面单：

- **目的 MAC 地址 → 收件地址**：说明这一帧在当前局域网中要交给哪个网络接口，交换机也据此决定如何转发。
- **源 MAC 地址 → 寄件地址**：说明这一帧来自哪个网络接口，交换机可以结合入端口学习“这个地址在哪个方向”，方便以后转发。
- **类型字段 → 包裹上的物品类别标签**：收到包裹后，还要知道交给谁处理。比如标明里面是 IPv4 或 ARP 数据，接收方才能交给对应的上层协议。

所以这三个字段分别回答了：**发给谁、谁发的、里面装的是什么协议的数据**。只知道收件地址还不够，因为接收后还需要正确分发和处理。

包裹中的物品对应数据字段；用于检查传输差错的 FCS 位于帧尾，不属于首部。
